## How CPU manages RAM?
Main memory and the registers built into the processor itself are the only general-purpose storage that the CPU can access directly. This means that any instructions being executed and any data being operated on by those instructions must reside in one of these directly accessible storage devices. If the data are not in memory, they must be moved there before the CPU can operate on them.
The CPU operates at a much faster rate than main memory can support. To address this performance gap, computer systems employ a memory hierarchy. Registers are the fastest form of storage, accessible within a single CPU clock cycle. Main memory access, in contrast, can take many clock cycles to complete, causing the processor to stall since it does not have the data required to complete the instruction it is executing. This situation is intolerable because of the frequency of memory accesses. To remedy this, a small, fast memory cache is added between the CPU and main memory. Cache memory is faster than main memory but slower than registers, providing an intermediate access speed that helps bridge the performance gap.

## Memory Management Unit (MMU)
The MMU is responsible for translating logical addresses (also called virtual addresses) generated by the CPU into physical addresses that correspond to actual locations in physical memory. This translation happens dynamically during program execution and is transparent to the running process.
The **logical address space is the set of all logical addresses generated by a program or CPU**, while the **physical address is the actual, real-world location in the computer's RAM corresponding to these logical addresses.** In schemes where logical and physical addresses differ (such as in paging and segmentation systems), we distinguish between these two types of addresses. The runtime mapping from virtual to physical addresses is performed by the MMU.
![[MMU workload.png| center | 650]]

#### This is how the **MMU** works using cache for faster data transfer: (not important)
When virtual addresses are used, the system designer may choose to place the cache between the processor and the MMU or between the MMU and main memory. A logical cache, also known as a virtual cache, stores data using virtual addresses. The processor accesses the cache directly, without going through the MMU. A physical cache stores data using main memory physical addresses.
![[MMU.png| center | 600]]
#### Importance of Base and Limit Registers:
A fundamental requirement of memory management is protection - ensuring that each process can access only the memory locations that belong to it and preventing processes from interfering with each other's memory or with the operating system's memory. One method of providing this protection uses two registers, typically called the base register and the limit register.

**Base register:** holds the smallest legal physical memory address that a process can access, essentially marking where the process's memory space begins.
**Limit register:** specifies the size of the range of legal addresses, defining how much memory the process is allowed to access.

When a program is running in user mode, every address generated by the CPU is checked against these registers. The CPU hardware compares every address generated in user mode with the registers to ensure it falls within the legal range. If a program attempts to access memory outside its designated space (either below the base address or beyond base plus limit), the hardware traps to the operating system, which treats the attempt as a fatal error. This trap is typically what causes a "segmentation fault" or "memory access violation" error.
For example, *if the base register holds 300040 and the limit register is 120900, then the program can legally access all addresses from 300040 through 420939 (inclusive).*
![[base and limit reg example.png| center | 400 center]]
**Memory Protection Mechanism:** when the CPU scheduler selects a process for execution, the dispatcher loads the base and limit registers with the correct values for that process as part of the context switch. Every address generated by a user process is then viewed as relative to the base register value. The hardware automatically adds the value in the base register to the address generated by the user process before sending it to memory, and simultaneously checks that the address is within the legal range specified by the limit register.
This scheme allows the operating system to change the value of the base register during a context switch, effectively allowing different processes to occupy different portions of physical memory. The mapping of logical to physical addresses in this scheme is performed at runtime by the addition of the base register value.
![[memory protection using base + limit reg.png| center | 600 center]]
## Bootstrap Process
The bootstrap program, or boot loader, is the first program that runs when a computer is powered on or rebooted. The term "bootstrap" comes from the phrase "pulling oneself up by one's bootstraps," reflecting the seemingly paradoxical nature of a computer starting itself up.
When a computer is first powered on or restarted, it needs to have an initial program to run. This program must be available immediately and must be stored in a form of memory that doesn't require the operating system to already be running. For this reason, the bootstrap program is typically stored in read-only memory (ROM) or electrically erasable programmable read-only memory (EEPROM), which is generally known as firmware within the computer hardware.
The bootstrap program is stored at a fixed, well-known location in memory. When the CPU is reset or powered on, the instruction register is loaded with a predefined memory location, and execution starts there. At this location resides the bootstrap program.

## Address Binding
Address binding in an OS is `the crucial process of mapping a program's logical (virtual) addresses to actual physical memory addresses`, allowing the CPU to find and access data and instructions in RAM, a task managed by the OS and Memory Management Unit (MMU).
#### The problem
A user program goes through several steps before being executed. Addresses may be represented in different ways during these steps. Addresses in the source program are generally symbolic (such as the variable name "count"). A compiler typically binds these symbolic addresses to relocatable addresses (such as "14 bytes from the beginning of this module"). The linkage editor or loader in turn binds the relocatable addresses to absolute addresses (such as memory location 74014). Each binding is a mapping from one address space to another.
![[Address Binding steps.png| center | 450 center]]
#### Timing of Address Binding
**1. Compile Time:** If it is known at compile time where the process will reside in memory, then absolute code can be generated by the compiler. For example, if you know that a user process will reside starting at location R, then the generated compiler code will start at that location and extend up from there. If, at some later time, the starting location changes, then it will be necessary to recompile this code.

**2. Load Time:** If it is not known at compile time where the process will reside in memory, then the compiler must generate relocatable code. In this case, final binding is delayed until load time. If the starting address changes, we need only reload the user code to incorporate this changed value.

**3. Execution Time:** If the process can be moved during its execution from one memory segment to another, then binding must be delayed until runtime. This scheme requires hardware support for address mapping, such as base and limit registers. Most general-purpose operating systems use this method. With execution-time binding, the addresses in the program remain as logical addresses throughout execution. Every time an address is referenced, the memory management unit (MMU) translates it to a physical address. This translation happens dynamically for every memory reference. Because the translation happens at runtime using hardware registers, the operating system can move a process in memory simply by updating the base register. The process itself is unaware of the physical location of its memory.
## Memory Allocation
**Memory allocation** is the process by which the operating system assigns portions of physical memory (RAM) to processes for their use. The OS must keep track of which parts of memory are available and which are in use, and it must have strategies for allocating memory efficiently.
### The Memory Allocation Problem
When a new process arrives and needs memory, the OS must:
1. Determine how much memory the process needs
2. Find available memory space
3. Assign that space to the process
4. Keep track of what's allocated and what's free
5. Reclaim memory when processes terminate
### Types of Memory Allocation:
#### Continuous Memory Allocation
Contiguous memory allocation is basically a method in which `a single contiguous section/part of memory is allocated to a process or file needing it.` Because of this, all the available memory space resides in the same place together, which means that the 2unused available memory partitions are not distributed in a random fashion here and there across the whole memory space.
The main memory is a combination of two main portions- one for the operating system and other for the user program. 
`We can achieve contiguous memory allocation by dividing the memory partitions into fixed size partitions.`
![[Contiguous memory illustration.png| center | 600 center]]
##### Types of Continuous Memory Allocation
1. **Fixed Partition:** Memory is divided into fixed-sized partitions at system startup. Each partition can hold exactly one process. **How it works:** 
	1. Memory is divided into fixed partitions during system initialization. 
	2. Partition sizes may be equal or unequal. 
	3. When a process arrives, it's assigned to the smallest partition that can accommodate it. 
	4. Each partition can hold only one process at a time. 
	**Problem:** If a process is smaller than the partition, the unused space within the partition is wasted. 
	Example: *40K process in 100K partition wastes 60K.*
2. **Dynamic Partition:** Partitions are created dynamically based on the exact size of the process. Memory is not divided in advance. **How it works:** 
	1. Initially, all memory is one large free block.
	2. When a process arrives, a partition of exactly the required size is created.
	3. When a process terminates, its memory becomes a free hole.
	4. Over time, memory becomes a collection of allocated blocks and free holes.
	As processes come and go, memory becomes fragmented into allocated blocks and free holes of various sizes. The OS must maintain a list of Allocated blocks and Free holes. *When a process needs memory, the OS must choose which free hole to allocate from.*
	**Allocation Strategies:**
		1. **First Fit:** Search the hole list from the beginning, stop at the first suitable hole and allocate the `FIRST hole that is BIG` enough.
		2. **Best Fit:** Search the entire hole list, choose the hole that leaves the smallest remainder and allocate the `SMALLEST` hole that is big enough
		3. **Worst Fit:** Search entire hole list, choose the largest hole and Allocate the `LARGEST` available hole.
	**Problem:** Free memory is broken into many small holes. Even though total free memory might be enough, it's scattered. Example: *Need 200K, but have 10 holes of 20K each = 200K total but unusable.*
#### Non Continuous Memory Allocation:
Non-Contiguous memory allocation is basically a method on the contrary to contiguous allocation method, `allocates the memory space present in different locations to the process as per it's requirements.` As all the available memory space is in a distributed pattern so the freely available memory space is also scattered here and there. This technique of memory allocation `helps to reduce the wastage of memory,` which eventually gives rise to Internal and external fragmentation.
![[Non Continuous Memory illustration.png| center | 600 center]]
It has the advantage of reducing memory wastage but it increases the overheads due to address translation, which results in slow execution.
##### Types of Non Continuous Memory Allocation
- ***Paging:*** It breaks processes into equal-sized pages and maps them to memory frames, mainly to eliminate external fragmentation.
- ***Segmentation:*** It divides processes into variable-sized logical segments (like code, data, stack), supporting protection, sharing, and logical organization.
- ***Segmented Paging:*** A hybrid technique that first divides processes into logical segments and then splits each segment into fixed-size pages, combining the benefits of segmentation and paging.
## Paging
Paging is the process of moving parts of a program, called pages, from secondary storage into the main memory (RAM). Remember in dynamic partitioning our main problem was external fragmentation, where we could not allocate 200K of space for a program even though we had enough free total memory. `Paging was invented to solve this problem completely.`

Instead of requiring a process to occupy one contiguous block of physical memory, **paging allows a process's memory to be divided into small fixed-size blocks that can be placed anywhere in physical memory.**

To keep track of where each page is stored in memory, the operating system uses a `page table`. This table shows the connection between the logical page numbers and the physical page frames (actual locations in RAM).
![[Paging Hardware.png|center| 600 center]]
**Pages (Logical Memory Blocks):** Fixed-size blocks of **logical (virtual) memory** that belong to a process. 
The page size (like the frame size) is defined by the hardware. The size of a page is a power of 2. If the size of the logical address space is $2^m$,and a page size is $2^n$ bytes, then the high order `m−n` bits of a logical address designate the page number, and the `n` low order bits designate the page offset. where `p` is an index into the page table and `d` is the displacement within the page.

**Frames (Physical Memory Blocks):** Fixed-size blocks of **physical (RAM) memory** where pages are actually stored.
The frame size (like the page size) is defined by the hardware and **must be equal to the page size**. The size of a frame is a power of 2. The selection of a power of 2 as a frame size makes the translation of a logical address into a frame number and frame offset particularly easy. If the size of the physical address space is $2^q$ bytes, and a frame size is $2^n$ bytes, then the high order `q-n` bits of a physical address designate the **frame number**, and the `n` low order bits designate the **frame offset** (which is the same as the page offset). `One Page occupies exactly one Frame. Mapping between page and frame is maintained by PAGE TABLE.`
therefore, **PAGE size = FRAME size**
### Paging Work Flow
In the below illustration we have a 32 bytes of physical memory and each page is 4 bytes long. If page offset n = 2 and logical address is m = 4 bits long. then let's explain how paging will work.
![[paging work procedure.png | center | 600 center]]
From the given information we get,
**Page size** = 4 bytes = 2² bytes, n = 2
**Logical memory** = 2$^4$= 16 bytes, m = 4 
**Number of Pages** = 16/4 = 4 pages
```
Page 0: [Addresses 0-3]     → Contains: a, b, c, d
Page 1: [Addresses 4-7]     → Contains: e, f, g, h
Page 2: [Addresses 8-11]   → Contains: i, j, k, l
Page 3: [Addresses 12-15] → Contains: m, n, o, p
```
**Physical Memory** = 32 bytes = 2$^5$ bytes, q = 5
**Frame size** = Page size = 4 bytes = 2² bytes, n = 2
**Number of Frames** = 32/4 = 8 frames
```
Frame 0: [Addresses 0-3]   → Empty (shown in blue/unused)
Frame 1: [Addresses 4-7]   → Contains: i, j, k, l (Page 2)
Frame 2: [Addresses 8-11]  → Contains: m, n, o, p (Page 3)
Frame 3: [Addresses 12-15] → Empty (shown in blue/unused)
Frame 4: [Addresses 16-19] → Empty (shown in blue/unused)
Frame 5: [Addresses 20-23] → Contains: a, b, c, d (Page 0)
Frame 6: [Addresses 24-27] → Contains: e, f, g, h (Page 1)
Frame 7: [Addresses 28-31] → Empty (shown in blue/unused)
```
Let's say we know the location of `g` in logical address, and using the Page table we have to find its physical address.
`g` belongs to Logical address = `0110`
```
Logical Address: 01|10
                 ││ └─→ Offset (2 bits)
                 └┴──→ Page number (2 bits)

Page Number (p) = 01 binary = 1 decimal → Page 1
Page Offset (d) = 10 binary = 2 decimal → Third byte in page
```
Upon looking into the page table we see that `Page 1` corresponds to `Frame 6`.
Therefore, we construct the physical address
```
Frame Number = 6 = 110 binary
Offset = 2 = 10 binary

Physical Address = 110|10 binary = 11010 binary = 26 decimal
```
in Physical memory 26th byte actually contains `g`. **This is how Paging works!**
### Problem with paging
Now there's a catch. It takes too much time to look up to data. Formally stating: Every memory access now requires TWO memory accesses:
1. One to read the page table entry
2. One to access the actual data
**This cuts performance in half**
### Solution to this
Using a `Translation Lookaside Buffer (TLB)`
The TLB is a special, fast-lookup hardware cache for page table entries. When the CPU generates a virtual address, it first looks up the page number in the TLB.
- **TLB Hit:*** It is the situation when, the page number is found in the TLB, the corresponding frame number is retrieved instantly.
- ***TLB Miss:*** It is the situation when, the page number is not found in the TLB, the CPU accesses the page table in main memory.
![[Paging TLB mechanism.png|center | 500 center]]
***Steps in TLB Hit:***
	1. CPU generates a virtual (logical) address. 
	2. It is checked in TLB (present). 
	3. The corresponding frame number is retrieved, which now tells where the main memory page lies. 

***Steps in TLB miss:***
	1. CPU generates a virtual (logical) address. 
	2. It is checked in TLB (not present). 
	3. Now the page number is matched to the page table residing in the main memory (assuming the page table contains all PTE). 
	4. The corresponding frame number is retrieved, which now tells where the main memory page lies. 
	5. The TLB is updated with new PTE (if space is not there, one of the replacement techniques comes into the picture i.e either FIFO, LRU or Second chance).

**Effective memory access time(EMAT):**
	TLB is used to reduce adequate memory access time as it is a high-speed associative cache.
	Formula: $EMAT=h×(c+m)+(1−h)×(c+n×m)$
	where, 
	- h is the hit ratio of the TLB,
	- m is the memory access time,
	- c is the TLB access time and
	- n represents the system level.
	**A higher hit ratio h significantly reduces EMAT, making the system efficient.**
## Demand Paging
**Demand paging** is an advanced memory management technique that builds upon basic paging by loading pages into memory **only when they are needed (demanded)** rather than loading the entire process into memory at once.
### The Core Concept
With demand paging, when a process starts execution:
- **NOT all pages are loaded into physical memory**
- Only the pages that are actually needed are brought into RAM
- Pages remain on disk until they are referenced
- This is also called `lazy loading` or `lazy swapping`
### Understanding the difference between Paging and Demand Paging
#### BASIC PAGING (What we discussed earlier)
**Loading Process:**
1. Process is created
2. **ALL pages of the process are loaded into physical memory** immediately
3. Page table entries are created for all pages
4. All pages point to valid frames in RAM
5. Process starts execution
#### Demand Paging
**Loading Process:**
1. Process is created
2. **NO pages are initially loaded** (or only the first page)
3. Page table entries are created but marked as "invalid" or "not in memory"
4. Process starts execution with minimal memory
5. Pages are loaded **on demand** as they are accessed
#### Page Fault
Due to the characteristics of Demand paging, there is a high chance that the required data is still not in the physical memory (system RAM), which causes a problem known as Page Fault. 
A page fault occurs when a program attempts to access data or code that is in its address space but is not currently located in the system RAM. This triggers a sequence of events where the operating system must manage the fault by loading the required data from secondary storage into RAM.
`Page faults are essential for implementing virtual memory systems that provide the illusion of a larger contiguous memory space`.
![[Page Fault.png|center|550 center]]
#### Handling Page Fault
**Scenario:** Process tries to access logical address in Page 2, but Page 2 is not in memory.
**Step 1: Process References Page**
```
CPU generates logical address
MMU extracts page number: Page 2
MMU checks page table
Page Table Entry for Page 2:
Valid bit = i (invalid bit, page not in memory)
↓
MMU triggers PAGE FAULT exception
```
**Step 2: Trap to Operating System**
```
CPU hardware:
1. Saves current process state
2. Transfers control to OS (page fault handler)
3. Process is blocked (waiting state)
```
**Step 3: OS Page Fault Handler**
```
OS checks:
1. Is this a valid reference? (within process address space)
   - If NO: terminate process (segmentation fault)
   - If YES: continue

2. Is the page on disk?
   - Get disk location from page table or auxiliary table
```
**Step 4: Bring in missing page to free frame**
```
OS looks for free frame:
- Check free frame list
- If no free frames: select victim page (page replacement)
  - Choose which page to evict (we'll cover algorithms)
  - If victim page modified: write to disk (page-out)
  - Update victim's page table entry (valid = v)
OS initiates disk I/O:
1. Schedule disk read operation
2. Read page from disk into selected frame
3. This is SLOW (milliseconds vs nanoseconds)
4. Process remains blocked during I/O
```
**Step 5: Reset Page Table**
```
When disk I/O completes:
1. Update page table entry:
   - Frame number = newly allocated frame
   - Valid bit = 1
2. Update auxiliary information (reference bits, etc.)
```
**Step 6: Restart Instruction**
```
1. Restore process state
2. Return from page fault handler
3. Restart the instruction that caused page fault
4. This time, page is in memory - no fault
5. Instruction executes successfully
```
## Page Replacement
In an operating system that uses paging, a page replacement algorithm is needed when a `page fault occurs` and no free page frame is available. In this case, one of the existing pages in memory must be replaced with the new page.
The virtual memory manager performs this by:
1. Selecting a victim page `(valid bit = i)` using a page replacement algorithm.
2. Marking its page table entry as **not present**.
3. If the page was modified (dirty), writing it back to disk before replacement.
The efficiency of a page replacement algorithm directly affects the page fault rate, which in turn impacts system performance.
### Policies
1. **First In First Out (FIFO):** In this algorithm, the operating system keeps track of all pages in the memory in a queue, the oldest page is in the front of the queue. When a page needs to be replaced page in the front of the queue is selected for removal.
2. **Least Recently Used (LRU):** In this algorithm, page will be replaced which is least recently used.
3. **Second Chance:** The Second Chance Page Replacement Algorithm is an improvement over FIFO (First-In, First-Out). FIFO may remove frequently used pages, but Second Chance reduces this problem by using a reference bit.
	1. When a page is accessed, its reference bit is set to 1.  
	2. During replacement, the algorithm checks pages in order:
		- If a page’s bit = 0, it is replaced.
		- If the bit = 1, it is reset to 0 and the page gets a “second chance,” moving to the back of the queue.
	This way, frequently used pages are less likely to be removed.
	Traditionally, Second Chance and its variant Clock were considered less efficient than LRU (Least Recently Used).
