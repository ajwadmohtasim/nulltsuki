## **Theory: Flex Fundamentals**

### **What is Flex?**

**Flex** (Fast Lexical Analyzer Generator) is a tool for generating scanners/lexical analyzers. It automates the process of writing lexical analysis code.

**Key Points:**

- Reads patterns defined in a `.l` or `.lex` file
- Produces a C program (`lex.yy.c`) that recognizes those patterns
- Widely used in compiler design courses
- Pre-installed on Linux, requires manual installation on Windows
- Requires a C compiler (GCC/MinGW) to compile generated code

### **Flex Workflow**

```terminal
	Lex Source Program (.l/.lex)
	          ↓
	[Lexical Compiler (Flex)]
			  ↓
	lex.yy.c (C Program)
			  ↓
	[C Compiler (GCC)]
			  ↓
	a.out/a.exe (Executable)
			  ↓
	Input Stream → Sequence of Tokens
```

**File Types:**

- **`.l` or `.lex`**: Lex source program (pattern definitions)
- **`lex.yy.c`**: C program generated by Flex
- **`a.out`/`a.exe`**: Executable lexical analyzer

## **Structure of Flex Program**

A Flex program consists of three sections separated by `%`:

```cpp
%{
    /* DEFINITIONS SECTION */
    /* Declarations of constants, variables, and regular definitions */
    /* Code here is copied directly to lex.yy.c */
    #include <stdio.h>
    int count = 0;
%}

%%
    /* RULES SECTION */
    /* Pattern {Action} format */
    /* Each pattern is a regular expression */
    [A-Z]    { printf("Capital letter: %s\n", yytext); count++; }
    [a-z]    { printf("Lowercase letter: %s\n", yytext); }
    .|\n     { /* ignore */ }

%%
    /* USER SUBROUTINES SECTION */
    /* C statements and additional functions */
    /* Can be compiled separately and loaded with lexical analyzer */
    int yywrap() { return 1; }
    
    int main() {
        yylex();
        printf("Total capitals: %d\n", count);
        return 0;
    }
```

### **Important Flex Functions and Variables**

|Function/Variable|Description|
|---|---|
|`yylex()`|Main flex function that runs the scanner and processes input|
|`yytext`|Character array containing the matched text|
|`yywrap()`|Called when end of input is reached; return 1 to stop, 0 to continue|
|`yyin`|File pointer for input (default: stdin)|
|`yyout`|File pointer for output (default: stdout)|

**Purpose:** Count the number of capital letters in input string

**Code: `capital.l`**

```c
%{
#include <stdio.h>
int count = 0;
%}

%%
[A-Z]  { printf("%s capital letter\n", yytext); count++; }
.      { printf("%s not a capital letter\n", yytext); }
\n     { return 0; }
%%

int yywrap() {
    return 1;
}

int main() {
    yylex();
    printf("\nNumber of Capital letters in the given input - %d\n", count);
    return 0;
}
```

**Explanation:**

- **Definition Section**: Declares `count` variable to track capitals
- **Rules Section**:
    - `[A-Z]`: Matches capital letters, increments counter

    - `\n`: Matches newline, stops input
- **User Subroutines**: `yywrap()` returns 1 (stop), `main()` runs scanner

**How to Run:**


### **Example 4: Valid Identifier Checker**

**Purpose:** Identify whether a string is a valid identifier or keyword

**Code: `identifier.l`**

```c
%{
#include <stdio.h>
#include <string.h>

char *keywords[] = {
    "int", "float", "if", "else", "while", 
    "for", "return", "main", "void", NULL
};

int isKeyword(char *word) {
    for (int i = 0; keywords[i] != NULL; i++) {
        if (strcmp(word, keywords[i]) == 0)
            return 1;
    }
    return 0;
}
%}

%%
[_a-zA-Z][_a-zA-Z0-9]*  {
    if (isKeyword(yytext))
        printf("%s : KEYWORD (Not a valid identifier)\n", yytext);
    else
        printf("%s : VALID IDENTIFIER\n", yytext);
}

[0-9][_a-zA-Z0-9]*  { 
    printf("%s : INVALID IDENTIFIER (Starts with digit)\n", yytext); 
}

.|\n  { /* Ignore other characters */ }
%%

int yywrap() {
    return 1;
}

int main() {
    printf("Enter identifiers (Ctrl+D to stop):\n");
    yylex();
    return 0;
}
```

**Identifier Rules:**

1. Must start with letter or underscore: `[_a-zA-Z]`
2. Can contain letters, digits, underscores: `[_a-zA-Z0-9]*`
3. Cannot be a reserved keyword

**How to Run:**

```terminal
# Step 1: Save as identifier.l
flex identifier.l

# Step 2: Compile
gcc lex.yy.c -o identifier.exe

# Step 3: Run
./identifier.exe

# Step 4: Test with various inputs
```

**Sample Test Cases:**

|Input|Output|Reason|
|---|---|---|
|`count`|VALID IDENTIFIER|Starts with letter|
|`_sum1`|VALID IDENTIFIER|Starts with underscore|
|`1count`|INVALID (Starts with digit)|Begins with number|
|`float`|KEYWORD (Not valid identifier)|Reserved keyword|
|`_value`|VALID IDENTIFIER|Valid format|
|`myVar123`|VALID IDENTIFIER|Letters and digits|
|`@value`|Ignored|Contains special character|

**Expected Output:**

```terminal

count
count : VALID IDENTIFIER
1sum

float : KEYWORD (Not a valid identifier)
```

## **Lab Questions & Answers**

### **Q1: What is Lex tool used for?**

**Answer:**

Lex (Lexical Analyzer Generator) is a tool used for generating lexical analyzers (scanners) for compilers. It is used to:

1. **Tokenize source code**: Break input into meaningful tokens
2. **Pattern matching**: Recognize patterns using regular expressions
3. **Automate lexical analysis**: Generate C code automatically from pattern specifications
4. **Simplify compiler construction**: Eliminate manual tokenization code
5. **Build text processing tools**: Create utilities for parsing and processing text

Lex reads a specification file (`.l`) containing regular expression patterns and actions, then produces a C program that implements the lexical analyzer.

### **Q2: List the different sections available in LEX code?**

**Answer:**

A Lex program consists of **three sections** separated by `%`:

**1. Definitions Section** (`%{` ... `%}`)

- C declarations (variables, functions, includes)
- Regular expression definitions
- Code copied directly to `lex.yy.c`

**2. Rules Section** (between first and second `%`)

- Pattern-action pairs
- Format: `pattern { action }`
- Patterns are regular expressions
- Actions are C code executed when pattern matches

**3. User Subroutines Section** (after second `%`)

- Additional C functions
- `main()` function
- `yywrap()` function
- Helper functions

**Example Structure:**

```c
%{
    /* Section 1: Definitions */
    #include <stdio.h>
    int count = 0;
%}

%%
    /* Section 2: Rules */
    [0-9]+  { printf("Number\n"); }
    [a-z]+  { printf("Word\n"); }

%%
    /* Section 3: User Subroutines */
    int main() {
        yylex();
        return 0;
    }
    
    int yywrap() { return 1; }
```

### **Q3: What is the input for LEX Compiler?**

**Answer:**

The input for LEX compiler is a **Lex specification file** with `.l` or `.lex` extension.

**Components of Input File:**

1. **Pattern Definitions**: Regular expressions defining tokens
2. **Actions**: C code to execute when patterns match
3. **C Code**: Variable declarations, functions, includes

**Example Input File (`scanner.l`):**

```c
%{
#include <stdio.h>
%}

%%
[0-9]+     printf("INTEGER");
[a-zA-Z]+  printf("IDENTIFIER");
%%

int main() { yylex(); return 0; }
int yywrap() { return 1; }
```

**Processing:**

```terminal
scanner.l → [flex] → lex.yy.c → [gcc] → a.exe
```

### **Q4: What is the output of LEX compiler?**

**Answer:**

The output of LEX compiler (Flex) is a **C source file named `lex.yy.c`**.

**Characteristics of `lex.yy.c`:**

1. **Contains**: Complete C implementation of lexical analyzer
2. **Includes**:
    - `yylex()` function (main scanner function)
    - Pattern matching logic (DFA implementation)
    - All code from definitions section
3. **Size**: Typically several thousand lines of C code
4. **Compilation**: Requires C compiler (GCC) to create executable

**Workflow:**

```terminal
Input: scanner.l
↓ [flex scanner.l]
Output: lex.yy.c
↓ [gcc lex.yy.c]
Output: a.exe (executable lexical analyzer)
```

### **Q5: Why do we need a lexical analyzer?**

**Answer:**

A lexical analyzer is essential for several reasons:

**1. Simplification**

- Separates low-level character handling from high-level syntax analysis
- Makes parser design simpler and cleaner

**2. Efficiency**

- Optimized for pattern matching
- Faster than parsing individual characters
- Uses efficient automata (DFA)

**3. Modularity**

- Independent phase that can be developed and tested separately
- Easy to modify token definitions without affecting parser

**4. Error Handling**

- Detects lexical errors early (invalid characters, malformed tokens)
- Provides better error messages with line numbers

**5. Portability**

- Hides machine-dependent input details
- Provides uniform interface to parser

**6. Preprocessing**

- Removes comments and whitespace
- Handles include files and macros (with preprocessor)

**Example:**

```c
int x = 10;  // Source code

↓ Lexical Analysis

Tokens: <KEYWORD, "int"> <ID, "x"> <OP, "="> <NUM, "10"> <PUNCT, ";">
```

### **Q6: What does a lexical analyzer do when prefixes of the input string match more than one pattern?**

**Answer:**

When multiple patterns match the input, lexical analyzers use **two disambiguation rules**:

**Rule 1: Longest Match (Maximal Munch)**

- Choose the pattern that matches the **longest** prefix
- Continue reading characters until no longer matches any pattern

**Rule 2: Rule Priority (First Match)**

- If multiple patterns match the same longest prefix
- Choose the pattern that appears **first** in the Flex specification

**Example 1: Longest Match**

```c
%%
if      { printf("KEYWORD: if\n"); }
[a-z]+  { printf("IDENTIFIER: %s\n", yytext); }
%%
```

Input: `ifcount`

- Pattern `if` matches "if" (2 chars)
- Pattern `[a-z]+` matches "ifcount" (7 chars)
- **Result**: Uses `[a-z]+` → `IDENTIFIER: ifcount`

**Example 2: Rule Priority**

```c
%%
[0-9]+     { printf("INTEGER\n"); }
[0-9]+\.[0-9]+  { printf("FLOAT\n"); }
%%
```

Input: `123`

- Both patterns could potentially match
- Pattern `[0-9]+` appears first
- **Result**: Uses first rule → `INTEGER`

**Example 3: Combined**

```c
%%
while      { printf("KEYWORD\n"); }
[a-z]+     { printf("IDENTIFIER\n"); }
%%
```

Input: `whileloop`

- "while" matches first pattern (5 chars)
- "whileloop" matches second pattern (9 chars)
- Longest match wins
- **Result**: `IDENTIFIER` (matches all 9 characters)

**Summary:**

1. **Longest match takes precedence** over shorter matches
2. **First rule wins** when multiple patterns match same length
3. This ensures **deterministic** behavior in lexical analysis

|---|---|---|

|`[A-Z]`|Uppercase letter|A, M, Z|
|`[a-zA-Z]`|Any letter|a, Z, m|
|`[0-9]+`|One or more digits|123, 5|
|`[a-z]*`|Zero or more lowercase|abc, ""|
|`[a-z]?`|Zero or one lowercase|a, ""|
|`\.`|Literal dot|.|
|`\n`|Newline||
|`\t`|Tab||
|`.`|Any character except newline|a, 5, @|
|`^`|Start of line||
|`$`|End of line||
|`|`|OR operator|
|`"+"`|Literal string|+|
